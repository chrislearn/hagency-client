I audited all 17 `page.jsx` routes and every `mockup/components/*.jsx`. For each operator action I checked the native branch, the i18n limitation strings, and the Rust `/console/api` router. The Rust side is `native/hagency/src/console.rs:64-90` plus the `console/*.rs` routers.

Paths below are relative to `RS-repo/`: `m/` means `mockup/` and `rs/` means `native/hagency/src/`.

## Framing facts (these explain most of the gaps)

- **Native build has 9 pages.** It stages and exports only usage, resources, resources/new, alerts, engagements, accounts, agents, project-sides and approvals (`m/scripts/build-native-console.mjs:18-27,79`). The server maps only those documents (`rs/console/assets.rs:178-196`). `/`, `/workforce`, `/capability`, `/config`, `/projects`, `/projects/new` and `/agents/[name]` do not exist in native.
- **Native rail links to 5 pages.** Only usage, resources, alerts, engagements and workforce (pointing at `/console/agents/`) are links. Capability, projects and config are greyed rows with the tooltip "This workflow is not yet available in the native console" (`m/components/Rail.jsx:91-92`, `m/lib/i18n.js:140`). Accounts, approvals and project-sides are built but have no rail entry.
- **Each session holds one scope.** Scopes are ReadOnly, Publication, Configuration, Account or AgentLifecycle (`rs/console/authority.rs:21-27,43-47`). The CLI refuses to combine management flags (`native/hagency/tests/cli.rs:632-642,703-708`).
  - Publishing, configuring, account work, lifecycle actions and alert triage each need a separate access link.
  - Alert triage needs the *configuration* scope (`rs/console/alerts.rs:117`).
- **Five server mutation groups have no UI.** The Rust routes and the JS wrappers exist, but no button calls them:
  - account prepare, retire and enrollment (`rs/console/accounts.rs:31-34`; `m/lib/native-api.js:414-429`)
  - project-side registration (`rs/console/project_sides.rs:23,100-139`)
  - engagement retire and cleanup-retry (`rs/console/engagements.rs:28-29`)
  - engagement refuse and orphaned-dispatch recovery (`rs/console/agents.rs:33,45,262-310`)
  - approval-grant revoke (`rs/console/approvals.rs:25`)
- **Two server routes refuse with 501:** agent start (`rs/console/agents.rs:175-194`, `agent_start_unavailable`) and agent preset (`rs/console/agents.rs:614-636`, `agent_preset_unavailable`).
- **Server-owned UNAVAILABLE lists:**
  - Agents: consumed, last_seen, online, tmux, pane, credential_home, workspace_path, seat (`rs/console/agents.rs:65-74`).
  - Project sides: label, api_base_url, credential_kind, has_credential, awaiting_install, sender_localpart, appservice_url, namespace, access_state, access_detail, allocated_tokens, project_name, owner (`rs/console/project_sides.rs:32-46`).
- **No server routes at all** exist for approve, whitelist, per-side allocation, invites, role offers or resource delete. I grepped `console.rs` and `console/*.rs`.

## UX defects in native mode

1. **Duplicate headers.** The h1 and h2 carry the same text: `NativeEngagements.jsx:65-66` and `NativeAlerts.jsx:63-64`.
2. **Pages with no PageHead.** Agents, project-sides, approvals and accounts have no h1, no tab title and no status strip (`NativeAgents.jsx:46`, `NativeProjectSides.jsx:37`, `NativeApprovals.jsx:68`, `NativeAccounts.jsx:30`).
3. **Heading identical to a button label.**
   - The editor title `nc.edit` "Edit configuration" (`resources/new/page.jsx:71`) is the same as the row button (`NativeResources.jsx:73`).
   - The create link "Create another configuration" (`NativeResources.jsx:52`) is the same as the submit button (`resources/new/page.jsx:465`).
4. **Contradictory label.** The agents page says "read-only" (`NativeAgents.jsx:46`) right next to Stop and Review buttons (`:87-88`).
5. **Stop gives no feedback.** `onClick={() => stopAgent(a.engagement_id)}` (`NativeAgents.jsx:87`) is not awaited: no pending state, no success or error message, no refresh, and errors become unhandled rejections.
6. **Blank screen when access is needed.** On phase `access`, `NativeAgents.jsx:40`, `NativeProjectSides.jsx:31`, `NativeEngagements.jsx:59` and `NativeAlerts.jsx:51` return `null`, with no `NativeAccessNotice`.
   - Approvals shows a generic "could not be read" instead (`NativeApprovals.jsx:48-55`).
   - Accounts maps *every* failure (busy, network) to "access required" (`accounts/page.jsx:20-21`), and its help text gives no CLI command (`i18n.js:148`).
7. **Empty-state text while loading.** The lists start as `[]`, so the page says "No engagements, no roster rows" and similar before the fetch finishes (`NativeAgents.jsx:54-57`, `NativeProjectSides.jsx:45`, `NativeEngagements.jsx:99`, `NativeAlerts.jsx:86`).
8. **Dropdown-only lists hide new items.**
   - The engagement is chosen only through a `<select>` over 16-row pages (`NativeUsage.jsx:46-49`).
   - A resource outside the current page shows as "Selected resource outside this page" instead of its name (`NativeResources.jsx:66`, `resources/new/page.jsx:151`). This happens right after the "Open saved resource" link (`resources/new/page.jsx:78`).
9. **Per-page counts look like totals.** The engagement state cards count only the current page, and Next page replaces rows (`NativeEngagements.jsx:38-42,132`), so "pending 0" can be wrong.
10. **No drill-down links.** Engagement rows do not link to usage (`NativeEngagements.jsx:116-124`), agent names are plain text (`NativeAgents.jsx:76`), and alert agents are plain text (`NativeAlerts.jsx:136`).
11. **Create leads to a dead end.** "Create another configuration" shows even when no source exists (`NativeResources.jsx:52`), and it lands on `nc.noSource`.
12. **Access-link dead ends.**
    - The account-scope ticket lands on `/console/accounts/` (`rs/console/client.rs:141-142`), which has no controls.
    - Lifecycle-only routes (register side, retire, refuse) have no UI even with a lifecycle link.
    - Without the lifecycle scope, the controls simply vanish with no hint about `--manage-agent-lifecycle` (`NativeAgents.jsx:70,85`).
    - The alert-triage notice names a "configuration management link" but shows no command (`i18n.js:415`, `NativeAlerts.jsx:157`).
13. **One scope per link.** Because of the single-scope rule, a routine session needs up to four different access links.
14. **Rail current-page marking (probable).** The agents check `/^\/console\/agents\/?$/` compares against `usePathname()`, which excludes basePath, so the Agents row is likely never marked current. `/resources/new/` marks no row (`Rail.jsx:91`).
15. **Stray logout.** "End access" sits inside the "Resource configuration" panel (`NativeResources.jsx:70`) and is absent from 6 of the 9 pages.
16. **Approvals has no refresh.** There is no Refresh button in the ready state (`NativeApprovals.jsx:64-126`).
17. **Wasted reads.** The data provider has no approvals or accounts branch, so those pages also fetch engagements plus a usage report (`Data.jsx:128-138`). The engagements page fetches an unused usage report (`native-api.js:132-133`). Accounts runs its own `exchangeAccess`, racing the provider's (`accounts/page.jsx:17`).
18. **TS-mode side effects.** `/project-sides` renders `null`, a blank page (`project-sides/page.jsx:15`), and `/accounts` always says "access required".

15. **Agent visibility:** no detail page, live pane, online or last-seen state (#22-23, #21).

19. **Fleet usage:** no fleet usage, charts or per-project/per-agent breakdown (#48).
20. **Navigation and access:** no front door; accounts, approvals and project-sides are unreachable from the rail; the one-scope-per-link rule forces juggling up to four CLI links; several pages go blank instead of explaining how to get access (#1-3, defects 6, 12, 13).
