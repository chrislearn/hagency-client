# Agent 执行设备与跨设备设置实施细则

本页替代 2026-10-07 身份/执行实例细则中的“独立执行实例”设计。Agent 仍是服务器范围的 Appservice 傀儡身份，创建者永久拥有它；设备变化不是主人变化，不引入转让。Project、Room 接入、主人私聊与资源配额规则继续有效。顶部返回列表入口以用户 2026-10-08 的新要求为准。

## 关系与数据

原实现的 `execution_instances.agent_id` 是主键，一个 Agent 最多一条记录，独立实例 ID 和名称没有第二种业务用途。新结构直接在 `agents` 保存 `execution_device_id`，通过设备/主人组合外键保证设备属于该永久主人。移除实例实体、实例表、名称、实例 ID 和旧实例 API。

关系是“一个 Agent 指定一个执行设备”，一台设备可以处理多个 Agent；执行设备字段不能设置全局唯一约束。每个 Agent 的 Room 和请求仍使用各自的资源政策及上下文。

新建 Agent 由服务器使用当前已授权设备赋值，不接收客户端提供的目标设备 ID，不需要设备选择表单。创建的原始幂等意图仍只包含名称和请求标识；在另一台设备恢复原创建请求不会悄悄改变原 Agent 的执行设备。

Agent 的既有 `generation` 用于设备设置的乐观并发控制，属于内部版本，不增加用户需要填写的业务字段。暂未指定设备的身份可以显示未绑定，已撤销的设备仍保留原关联以准确显示不可用，不偷偷绑定其他设备。

## API 与执行权限

- Agent 列表及详情包含 `executionDeviceId`；设备列表提供友好名称及撤销状态，当前设备由授权上下文确认。
- `GET agents/{id}` 返回当前 Agent；`PUT agents/{id}/execution-device` 仅接收 `expectedGeneration`，目标强制为发起请求的当前授权设备。
- 更新核对永久主人、当前设备授权、设备未撤销、Agent 未退役和预期版本。同设备的有效重复设置不更新版本、不撤销正常租约。
- 修改到另一台设备时提升 Agent 版本、撤销旧执行租约。未开始的派发恢复等待；已经开始而结果不确定的执行保留 `unknown`，不作为全新任务重复启动。旧设备不能确认、继续派发或提交新回复。
- 执行设备分配与租约、Codex 就绪、预算设置、逐 Room 显式启动是不同状态。绑定本机不代表 Agent 已在线或已经消耗资源。
- 旧实例 API 不保留兼容入口。Discovery 协议升为 3，客户端明确拒绝旧契约和普通 Matrix 服务器。

## 页面呈现

Agents 列表卡片和详情使用设备 badge，标识“本机”“其他设备”“未绑定”“设备不可用”。展示友好设备名，长设备 ID 不占主文案。设备信息尚未取得时显示加载状态，不据此允许运行或修改资源。

本机 Agent 不显示设备下拉框或实例名称，只显示明确的本机处理状态。在设置页，他机、未绑定或设备不可用的 Agent 提供“改由本机处理”；操作提示会停止旧设备的后续执行，本地资源和费用账本不会自动复制。用户确认后以读到的 Agent 版本提交，冲突要求刷新，不能自动覆盖别人刚保存的设置。

其他设备的 Agent 仍可管理身份状态、房间接入和邀请。Codex 资源、配额、请求策略和运行页说明这些设置由执行设备管理，在本机未取得执行权时禁止编辑、启动或把本机旧配置展示为远端实际配置。接管后需要在当前设备完成资源/额度设置，并明确启动需要服务的 Room；不自动启动、不绕过预算、不要求服务器管理员审批。

## 发布与验收

生产新部署直接使用新领域结构；服务器不自动读取旧实例表、不双写、不包含迁移兼容分支。本地已有测试身份和消息不能为了界面调整而删除，维护时先停止两端运行、保存私有数据库备份，再一次性将已分配设备复制到 Agent 字段并移除旧表。未分配的原身份保持未绑定；Palpo、Pasion 和已有傀儡、Room、消息、账本不重建。

验收需覆盖：创建默认本机、幂等恢复不改设备、主人隔离、其他设备拒绝启动、同设备设置不破坏租约、版本冲突、设备撤销、A→B→A 后旧租约不能复活、已经运行的未知结果不重放；同时检查 Desktop 和 client console 的设备 badge、他机资源阻挡、返回列表、设备切换后版本更新，以及旧实例路由被拒绝。

实现与实测结果在本轮各端冻结、部署并验收后追加。
