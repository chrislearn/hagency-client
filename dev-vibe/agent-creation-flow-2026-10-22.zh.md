# Agent 创建与错误反馈整理

## 用户流程

1. “新建 Agent”只负责名称和服务范围。进入时清除上一次操作的提示与草稿请求标识。
2. 创建期间在按钮上显示“正在创建…”和进度标记，禁止重复提交和修改在途字段。
3. 创建成功后打开该 Agent 的模型设置，提示连接本地账号、选择并保存模型；保存后提供“下一步：开启服务”。不自动选择模型、启动服务或发送消息。
4. 房间是可选的后续设置。已有但未绑定房间的 Agent，不限制创建另一个 Agent。

## 请求状态

| 状态 | 显示与操作 | 创建其他 Agent |
| --- | --- | --- |
| 服务端明确拒绝 | 红色失败卡；可纠正后重试，或收起失败记录 | 允许 |
| 创建中 | 正在创建；可查询结果 | 允许 |
| 网络或响应异常，结果未知 | 黄色提示；查询结果，或用原标识安全重试 | 不同请求允许；相同未确认请求保留原标识 |
| 已创建但尚未配置模型/房间 | 正常 Agent 卡片及下一步设置 | 允许 |

“查询结果”是 GET，不执行创建或绑定。“重试此请求”才允许重新发送，并保持原 payload 和幂等键。每次重新发送前持久化 unknown，防止一次曾被拒绝的请求在重试超时后仍被误认为可以安全收起。

失败记录使用 rejected，收起后使用 dismissed，审计文件保留。只有明确被拒绝的请求可收起，未知结果不能被丢弃。持久化错误仅接受 owner API 约定的有界机器码，不保存原始响应或凭据。

## 统一反馈

新增 shared/feedback.rs 的 InlineNotice：状态图标、语义背景/边框、醒目标题、可换行说明、可选下一步按钮、可展开诊断、可选关闭。错误不自动消失；切换操作或修改表单后清除相应提示。技术错误码放在详情，已确认拒绝不会再显示“结果未确认”。

Agent/Project 管理、模型保存、登录服务器连接和房间加载使用该组件；全局通知共用语义色板，发送失败条也采用相同危险色背景和边框。模型保存失败只在保存位置显示一次，不再上下重复。
