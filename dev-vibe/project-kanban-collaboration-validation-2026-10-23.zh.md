# 项目看板协作改进与原生验证（2026-10-23）

## 本轮结果

仅修改 Client 和 Server，两个仓库都在 `codex/project-kanban`。Cloud 无产品代码变更。

- 评论草稿按当前账号内的项目、任务隔离。切卡、关闭再打开会恢复本任务草稿；发送成功仅清除此任务的草稿。账号变化时清空。草稿仅在本次运行期间保留，没有承诺重启恢复。
- 详情侧栏扩大到 420 px，保留滚动条间距；窄窗口切换为完整详情区域。增加「任务详情 / 讨论与动态」页签，字段前置，评论和变更记录可一键访问。状态移动控件保留在详情顶部。
- 增加「分配给我」「我的任务」。成员选择优先显示简短名字，同名时显示完整 Matrix ID，离开项目的历史负责人仍有明确标记。
- 项目通知箱显示未读数，支持打开对应任务、单条已读、全部已读及较早通知分页。异步响应绑定账号、项目、请求和详情代次，避免旧通知、图片回包打开另一张卡。
- 通知接收人为当前项目成员中的创建人、现任和前任负责人、最近最多 100 位讨论参与者，以及评论中明确提到完整 Matrix ID 的成员；不通知操作者本人。重复请求不会重复发通知。
- 变更记录保存字段前后值；描述记录发生变更，清单记录完成数量变化，评论和附件记录摘要。历史记录不回填虚构差异。
- 附件支持原生文件选择、上传、PNG/JPEG 预览、原文件下载；卡片显示附件和评论数量。单文件最多 2 MiB，每个任务最多 20 个有效附件、40 MiB 留存字节。图片预览有尺寸和内存上限。

## 原生实测

在 `/tmp/HagencyLocal.app` 与 `/tmp/HagencyBob.app` 两个完整客户端中操作，分别使用隔离的 Alice 和 Bob 测试账号。客户端从项目列表 → 项目详情 → 看板正常进入；走真实 SDK 会话恢复、NativeOwner 授权、Server HTTP 和 PostgreSQL。只有 Pasion/Matrix 身份及同步来源是明确的本地测试 fixture，不把它当作真实远端 Matrix 的联调结论。

1. 在 #5 输入未发送评论，关闭后进入 #6：「讨论与动态」显示空评论编辑器；返回 #5 后恢复原草稿，未向 Server 发布这条草稿。
2. 在 #6 点击「分配给我」并保存，卡片负责人从 bob 变为 alice。
3. Bob 从完整项目流程进入看板，看到 1 条通知；通知内容显示「负责人：bob → alice」。点击后打开 #6，未读数变成 0。
4. Bob 发布带粗体 Markdown 和 `@alice:example.test` 的本地测试评论，评论正常渲染、编辑器清空。Alice 再次打开看板看到对应未读通知。
5. 从系统文件对话框选择测试 PNG，上传后 #6 显示附件数量；点击附件名能看到图片。通过系统保存对话框下载副本，原文件与下载文件 SHA-256 一致：`f108d940a9d1fbf06cc86e7c49967d826e91ca7555089692b3c10b77b772aa2e`。
6. 动态区能看到改派前后值、评论摘要和附件文件名。实测发现并修正了状态区的页签可见条件、通知列表填充行重复显示空状态的问题。

最终构建复查：「我的任务」仅显示 alice 负责的任务，清除筛选后恢复全部；通知列表不再重复显示空状态，状态区正常显示。

- Server 在独立临时 PostgreSQL 数据库运行全套：90 passed、0 ignored。涵盖通知/已读隔离、字段差异、附件幂等、跨任务与撤销成员拒绝、附件专用大请求路由以及普通评论请求体上限保持生效。
- Server all-target strict Clippy 通过；OpenAPI 校验 77 个 owner 操作、4 个 appservice 操作及 13 个校验器自测通过。
- 两端 diff whitespace 检查通过。构建仍有既有依赖 patch 提示及 macOS 大型 `__eh_frame` 链接警告。

## 边界

通知是项目内站内通知，当前看板前台活跃时刷新，返回时同步；不包含系统级推送、邮件、截止日期定时提醒或全局跨项目收件箱。外部 Markdown 图片 URL 仍不自动请求；图片通过任务附件展示，目前没有正文内嵌附件语法、剪贴板贴图或拖入文件。附件移除接口已有，客户端本轮提供上传、预览、下载入口。

协议升级为 `project-board-v3`，Server 增量迁移版本 3；需搭配本轮 Client/Server，旧 v2 客户端不会声明兼容。没有部署到远端，也没有推送分支。
