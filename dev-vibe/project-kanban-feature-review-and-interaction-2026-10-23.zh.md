# 看板功能复核与原生交互修复（2026-10-23）

## 功能覆盖

当前交付的是基础多人共享看板，并非完整项目管理套件。以下区分已经实现的功能、
本次实际原生操作的证据和仍未实现的能力。

| 常见能力 | 当前覆盖情况 |
| --- | --- |
| 项目看板、状态列、列计数 | 一个有效 Project 一块板、五个固定状态；计数来自 Server |
| 创建与编辑 | 标题、纯文本描述、优先级、标签、一个人工负责人、日期；本轮增加按列新建和创建状态选择 |
| 跨列移动、列内排序 | 服务端 rank/版本/邻居校验；整卡鼠标拖动、触控把手、拖动预览、边缘滚动、菜单移至顶部/底部 |
| 浏览大量卡片 | 列内虚拟化、独立纵向滚动、横向滚动、有界分页；本轮实际拖动两种滚动条 |
| 搜索筛选 | 标题、状态、负责人、标签、逾期、归档；本轮增加清除筛选和滚动位置复位 |
| 归档与恢复 | 已实现并实测；无永久删除接口 |
| 评论与活动 | 追加纯文本评论、操作者/本地时间/操作类型、有界分页；本轮补分页晚到响应隔离和输入错误提示；无评论编辑删除、@通知或字段级 diff |
| 共享与并发 | 当前成员授权、版本冲突、原始幂等请求、提交序号、前台轮询；不提供离线写入或退出应用后的草稿恢复 |
| 界面与操作反馈 | 中英文、主题、窄窗详情、加载/保存/冲突/错误状态；本轮增加固定顶部保存按钮、卡片边框、优先级与逾期提示 |
| 可配置流程 | 自定义列、WIP 限制、多板未实现 |
| 任务分解 | 子任务、清单、依赖、里程碑未实现 |
| 内容与协作增强 | 附件、消息关联、到期提醒、通知偏好未实现 |
| 管理与分析 | 批量操作、导入导出、趋势/周期统计、细粒度角色未实现；已有基础列计数 |
| 扩展平台与执行 | Web、Agent 自动执行、离线协作、E2EE 未实现 |

本轮优先修复核心交互、补齐基础操作反馈。下一批较有价值的增强是 WIP、清单/子任务、
提醒；附件、复杂统计和跨平台能力仍需对应的数据与权限设计，不能视为已完成。

## 冻结窗口的根因

上次启动的是 `project_board_preview` 只读设计入口，它设置 `active = false`。
`ProjectBoard::handle_event` 立即返回，导致不只写操作，连滚动条和视图事件也被挡住。
之前的脚本/布局和 NativeOwner API 测试没有覆盖这个入口的真实事件流，因此未发现。
不能把“同一组件绘制出来”当作“界面已经可操作”的证明。

修复后，只读入口仍会转发视图事件，允许滚动；实际操作验收改用新入口
`project_board_interactive`。它使用真实 NativeOwner、真实 Server API 和 PostgreSQL，
只显式替代本地 Pasion introspection/Matrix 成员来源，不维护另一套本地任务实现。
入口只接受标识明确的 loopback fixture，连接方法仅在 debug 构建提供。生产路径仍从
当前 SDK 账号取得 Service，身份与晚到结果隔离没有被关闭。

另修复了这些实际问题：

- 卡片原先只能抓很小的把手；现在鼠标可拖整卡，触控保留把手以便区分列表滚动。
- 自定义卡片原先缺少圆角边框 shader；现补齐，不再依赖无效的普通 View 边框属性。
- 筛选到空列时，旧 PortalList 滚动锚点会藏住空状态；现重置并钳制滚动位置。
- 横向自动滚动改从实际视图位置计算，避免手动滚动后从旧缓存位置跳动。
- 保存与冲突处理入口固定在详情顶部，避免长描述/评论把保存按钮挤出视口。
- 评论/活动分页按各自最新请求代次应用，早发晚到的一页不能覆盖用户刚切到的页面。
- 保存、移动、评论按钮的可用状态与草稿/归档/提交状态一致；评论长度错误有反馈。

## 实际执行的原生操作

使用本机 macOS 窗口 `Hagency · Project board`，16 张初始卡片，独立数据库
`kanban_interactive`。通过 CUA 操作控件，再只读查询 SQL 核对持久化结果：

| 操作 | 观察结果 |
| --- | --- |
| 拖动整张 #1 从待办到进行中 | 列计数 8/2 → 7/3，SQL state=in_progress、version=2 |
| 再拖 #1 到同列首位 | SQL rank=512，在 #9(rank1024)、#10(rank2048) 之前，version=3 |
| 拖动列内滚动条 | 待办从顶部卡片滚到 #6/#7/#8 |
| 拖动横向滚动条 | 详情保持打开，板面滚到完成列 |
| 从待验收列的 + 创建任务 | #17 直接落在 in_review，中文标题、标签、日期正确入库 |
| 修改优先级 | #17 priority=high，version=2；卡片显示高优先级色 |
| 添加评论 | 真实 comments 表有对应正文；详情有操作者和时间 |
| 归档、恢复 | #17 archived_at 有值/version3，然后清空/version4，活动保留 |
| 顶部固定保存 | 无修改时禁用；编辑标题后启用，保存得到 #17/version5 |
| 标题查询、清除查询 | 匹配计数为1，清除后恢复全板；空状态与滚动复位另有回归测试 |
| 重新启动窗口 | 原来移动、新建、编辑、评论和恢复结果仍在；种子请求重放，不覆盖用户修改 |

本轮操作的是显式测试身份和测试数据库，不是用户的真实 Matrix 账号或生产数据。
源代码功能验证不等于 Windows/Linux、高 DPI、真实双桌面或备份恢复验收。

  本次新增原生手动操作使用同一 Server 实现。

启动 Server 仓库的 `project_board_fixture`，将 `HAGENCY_AGENT_TEST_DATABASE_URL` 指向
独立的 loopback `kanban_` 数据库，并用 `HAGENCY_BOARD_FIXTURE_INFO` 输出连接信息。
然后在 Client 中运行：

```sh
HAGENCY_BOARD_FIXTURE_INFO=/tmp/hagency-kanban-interactive-info.json \
  cargo +1.99.0 run --locked -p hagency-app --example project_board_interactive
```

可加 `-- --bob` 启动第二个测试成员窗口，或 `-- --dark` 检查暗色主题。只有 Alice
入口使用固定幂等请求种一次初始数据；Bob 不重新创建种子卡片。默认数据目录隔离到
系统临时目录的 `hagency-kanban-interactive`，可用 `HAGENCY_APP_DATA_DIR` 显式覆盖。

本机 LaunchServices 启动的新 debug bundle 曾阻塞在源目录 mkdir/resource open。
通过实际进程栈定位后，验收窗口使用隔离临时数据，并用 `HAGENCY_BOARD_RESOURCE_DIR`
指向按 crate 名打包的本地资源；不修改系统权限或生产应用配置。普通源码运行无需
这个资源覆盖。打包目录结构为 `<root>/hagency_app/resources`、
`<root>/makepad_widgets/resources` 等现有 Makepad 依赖布局。

开发窗口和 loopback Server 留在运行状态供继续操作；未部署或推送。
