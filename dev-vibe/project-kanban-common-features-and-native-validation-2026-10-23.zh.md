# 看板常用功能扩展与原生验收（2026-10-23）

本轮在 Server、Client 的 `codex/project-kanban` 分支完成。Cloud 产品代码无需修改。
两端一起升级到 `project-board-v2`；固定五列的旧客户端明确报告能力不支持。

## 功能覆盖

| 功能 | 实现和边界 |
| --- | --- |
| 自定义列 | 2–12 列；新增、改名、左右排序、删除空列；稳定 ID；至少一个完成列。含未归档或已归档任务的列禁止删除，须先移走任务。 |
| WIP | 每列可设 1–10000 上限或不限；表头显示全列占用/上限并高亮满额；筛选不改变占用。Server 在事务锁内拒绝超限创建、跨列移动与恢复；允许列内排序和编辑。降低上限可以形成超限警示。 |
| 子任务 | 同 Project 一层父子关系，每父任务最多 100 个；独立状态、负责人、日期、归档生命周期；父详情列表与完成进度、子任务返回父任务和解除关联。创建入口在父任务详情。不会自动完成或归档父任务。 |
| 清单 | 每任务最多 100 项，每项 1–160 字；添加、改名、删除、上移排序、勾选、完成计数。随顶部“保存任务”同步；版本冲突保留清单与父关系草稿，未知保存重试原请求。 |
| 界面 | 独立列设置面板、行内输入和明确校验反馈；详情顶部固定保存；任务卡进度摘要；原有横纵滚动、拖动、筛选和窄窗布局继续保留。 |

配置使用看板序列号；其他成员先修改后，草稿保留，需审阅并采用最新看板版本再保存。
创建任务草稿按稳定列 ID 固定目标；外部列重排不会悄悄把草稿改投另一列。

## 原生实操证据

使用本机 macOS `Hagency · Project board` 窗口；`project_board_interactive` 运行相同的
生产看板组件，通过真实 NativeOwner → Server API → PostgreSQL 保存。仅本地测试
Pasion introspection 和 Matrix 成员来源为显式 fixture；不把它当作真实 Matrix 账号验收。

通过 CUA 实际执行：

1. 添加“质量验证”，设 WIP=1，从末尾移到第二列并保存；新列立即出现。
2. 整卡拖动 #2 进入该列，显示 1/1；拖动 #3 再进入被拒绝，显示 WIP 原因，卡片保留原列。
3. 在 #2 添加两条清单、勾选一条并保存；随后将第二项上移、改名再保存，卡片和详情显示 1/2。
4. 从 #2 创建 #18“子任务：核对原生界面与持久化”；保存后返回父任务，列表显示 0/1。
5. 打开 #18，通过状态菜单移到“完成”；返回 #2，列表和卡片进度变为 1/1，父任务仍在质量验证列。
6. 在列设置草稿中删除仍有任务的列，保存被服务端拒绝并提示先移走任务；取消草稿后原配置完整。
7. 退出客户端、更新并重启客户端及本地 Server；重新打开 #2，列位置/WIP、清单内容/顺序/勾选、子任务关系/完成状态均保留。

只读 SQL 回执 `/tmp/hagency-kanban-v2-native-receipt.json`：schema 版本 2；质量验证位于
position=1、limit=1；#2 version=4，清单第一项“重开后检查列、清单和子任务”未勾选，
第二项“确认 WIP 限制和跨列拖动”已勾选；#18 version=2、state=done、parentId 指向 #2。
旧任务和 v1 种子原始回执保留；重启过程中没有生成重复种子任务。

窗口和仅供该窗口使用的本地测试 Server/PostgreSQL 保持运行，便于继续查看。
